# Product Strategy

## Purpose

This book defines who Lumora Academy's product serves, phase by phase, and the principles that guide what's in scope versus not yet. Pricing and monetization belong to [Business Strategy](../02-business-strategy/index.md) (not yet written) — this book is about users and scope, not revenue.

## Status

Version: 1.1 foundation draft. User groups are grounded in the [Roadmap](../25-roadmap/index.md)'s phased scope; deeper positioning depends on Business Strategy, which doesn't exist yet.

## Who the product serves, by phase

Directly from the [Roadmap](../25-roadmap/index.md):

| Phase | User groups added |
|---|---|
| Phase 1 — Core Platform | Students, parents, admins (student portal, parent portal, admin portal) |
| Phase 2 — AI Platform | Same users, now with AI-assisted lessons, quizzes, and tutoring |
| Phase 3 — Expansion | Teachers (teacher tools), schools (school edition), marketplace participants |

## Scope principle

Per the [Constitution](../00-constitution/index.md#non-negotiable-principles) principles 1 and 2 (students come first; learning before technology): a feature earns a place in scope by improving the learning experience for one of the user groups above, not by being technically interesting. If a proposed feature can't name which user group it serves and how, it isn't ready for a feature spec yet ([Development Standards](../08-development-standards/index.md#feature-workflow)).
